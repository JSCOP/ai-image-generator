# Rust `image-cli`와 Python `tools/ai_image.py`의 의도된 차이

`crates/image-cli/tests/parity.rs`는 같은 가짜 제공자에 같은 spec을 보내고 두 CLI의 결과 JSON, 파일 목록, 이미지 크기, 기록 JSON, 제공자가 받은 요청 본문을 비교합니다. 아래 항목만 비교에서 빼며, 이 목록은 테스트의 `DROPPED_KEYS`·`DROPPED_FAILURE_KEYS`와 같아야 합니다. 설계 근거는 `docs/superpowers/specs/2026-10-18-image-studio-rust-app-design.md`입니다.

| 차이 | Rust 동작 | 이유 (설계 절) |
|---|---|---|
| 머신별 기본 주소 | 연결은 spec `profile`/`--profile` → 프로세스 `CLIPROXY_BASE_URL` → Windows 사용자 `CLIPROXY_BASE_URL` → 기본 프로필 순서로 정하고, 모두 없으면 네트워크 호출 전에 오류. `DESKTOP-SB818KQ`/Tailscale 주소 자동 선택 없음 | 배포본이 소유자 PC로 요청하지 않게 (§5.2) |
| Responses API 경로 | 옮기지 않음. `gpt-image-*`, `gemini-*-image`, `grok-imagine-*` 외 모델은 `unsupported`. spec `model` 키는 무시하고 `warnings`에 알림 | 현재 모델은 모두 Images API 또는 Gemini native (§5.1) |
| 리다이렉트 | 모델 조회·생성·편집 모두 따라가지 않고 `redirect` 오류. Python도 2026-10-18 수정(`fix: stop following redirects`)으로 같아짐 | API 키가 다른 호스트로 가지 않게 (§5.4, 검토 P1-01) |
| 기록 JSON 새 필드 | `status`(pending/complete/failed), `request_id`, `request_hash`, `background`, `fit`(요청한 방식), `fit_applied`(실제로 한 일: `none`/`cover`/`contain`/`original`), `provider_size`, `saved_size`, `sha256`, `alpha`, `connection_source`, `profile_id`(프로필 연결일 때만), `error`, `engine`. Python 키는 모두 같은 값으로 유지 | 이미지와 기록을 하나의 완료 결과로 공개 (§5.4, P1-05) |
| 실패 기록 | 실패하면 `status:"failed"`와 오류 구조를 남김. Python은 요청 전 기록만 남김 | 갤러리가 완료/실패를 구분 (§7.5) |
| 동시 실행 | 같은 출력 경로를 다른 실행이 쓰는 중이면 API 호출 없이 `conflict` 실패 | 이중 과금·기록 뒤섞임 방지 (§5.4) |
| resume 판정 | 파일 존재만이 아니라 기록의 `request_hash`·`sha256`과 이미지 디코딩까지 확인. 다른 요청으로 만든 파일이면 건드리지 않고 `conflict`. 기록 파일이 없거나 `status`가 없는 유효한 Python 기록이면 이미지가 열릴 때 완료로 인정. 이미지가 있는데 기록을 읽을 수 없거나 JSON으로 해석되지 않으면 손상으로 보고 `conflict`(재사용·덮어쓰기·생성 요청 없음). 이미지가 없으면 손상된 기록은 새 기록으로 교체. 판정은 출력 lock을 잡은 뒤 다시 하므로, 다른 실행이 먼저 완료한 기록은 덮어쓰지 않음 | 다른 프롬프트의 결과를 재사용하지 않게 (§5.4) |
| 실패 사유 문구 | `failures[].reason`은 `HTTP 400: rejected`처럼 정제한 한 줄. Python은 자식 프로세스 stderr 마지막 줄. 대신 `failures[].error`에 `category`, `provider_code`, `http_status`, `retryable` | 원인 구분과 키 제거 (§5.4) |
| 최상위 오류 | `error_category`를 함께 냄 | 같은 이유 |
| 새 spec 키 | `background`, `fit` 지원(single·jobs·batch 모두 같은 검증, batch는 최상위 값을 모든 계획에 적용). `mask`(single 모드만, 첫 참조 이미지와 같은 크기 PNG, 알파 0 = 수정 영역, `size`는 원본 크기)는 칠한 곳 주변 잘라낸 그림과 흑백 안내 그림만 보내고 결과를 칠한 곳에만 합성(밖은 원본 그대로). jobs·batch의 `mask`, `keep_outside_mask:false`, `remove_background:true`는 유료 호출 전에 `unsupported`로 거부. 투명 배경은 CLIProxyAPI의 `gpt-image-2.5`도 허용(2026-10-19 실측). 최상위 `profile`은 지원(Python에는 없음), job 안의 `profile`은 `unsupported`(한 실행은 한 연결) | 조용히 무시하지 않음 (§5.2, P1-04) |
| 연결 프로필 | `image-cli profile list/add/update/remove/default/check`와 `--profile NAME`. 프로필(종류 `cliproxy`·`openai`·`gemini`·`xai`·`openai_compatible` + 주소 + 키 참조)은 `IMAGE_STUDIO_HOME` 또는 `%APPDATA%\ImageStudio\profiles.json`, 키는 Windows 자격 증명 관리자(`ImageStudio`, 사용자 = 프로필 id)에만 저장. 명시한 프로필이 없거나 키가 없으면 다른 출처를 빌리지 않고 `invalid_request`. 손으로 고친 `profiles.json`도 읽을 때 항목마다 이름·주소·동시 실행 수(1~32)·중복을 다시 검사해 잘못된 항목을 짚어 `invalid_request`로 알리고 파일은 덮어쓰지 않음. 목록에 없는 기본 프로필은 "기본 없음"으로 봄. Gemini 주소에 `/v1beta` 경로가 있으면 "호스트만 입력" 오류. `http://`라도 루프백·사설망·Tailscale(100.64/10, `fd7a:115c:a1e0::/48`, `*.ts.net`)·점 없는 단일 이름(MagicDNS 짧은 이름 등)이면 경고 없음. Python에는 없음 | 앱과 CLI가 같은 연결 설정을 씀, 키 평문 금지 (§6.1) |
| 공식 API 어댑터 | OpenAI(`gpt-image-*`, Bearer, JSON 편집, 참조 최대 16장. 공식 ID가 아닌 접미사 없는 `gpt-image-2.5`(실행 기본값)는 `-sunburst`/`-flare`를 쓰라는 `unsupported`, 몰래 바꾸지 않음), Gemini(`gemini-*image*`, `x-goog-api-key`, `/v1beta/models` 페이지 처리, 후보 없이 `promptFeedback.blockReason`이면 재시도하지 않는 `provider` 오류와 `provider_code`=blockReason), xAI(`grok-imagine-image*`만, `grok-imagine-video*`는 `unsupported`, JSON `/images/edits`, `grok-imagine-image-2.0` 참조 최대 5장, 그 밖의 grok 1장). 종류와 모델이 맞지 않으면 유료 호출 전에 `unsupported`. 공식 API 직접 호출은 문서 근거(2026-10-18)이며 미실측 | 공급자별 요청 형식 차이 (§6.3, §6.4) |
| 동시 실행 기본값 | `cliproxy`·`openai_compatible` 30(Python과 같음), `openai`·`gemini`·`xai` 4. 프로필 `concurrency` → spec `concurrency` 순서로 덮어씀 | 공식 API 요금·속도 제한에 보수적으로 (§6.1) |
| 연결 상태 기록 | 프로필로 실제 생성하면 마지막 결과를 `status.json`에 남기고 `profile check`의 `last_generation`으로 보여 줌. 성공, 또는 권한(403)·지출 한도/할당량(402 등)·속도 제한(429) 응답만 기록하고 네트워크·DNS·시간 초과·TLS 실패, 401, 404, 5xx는 이전 값을 그대로 둠. `profile check`는 생성하지 않으며 401만 키 거부(`authenticated:false`)로 보고, 403/402/429 응답은 키가 받아들여진 것(`authenticated:true`, 오류 구분은 그대로) | "실제 생성 가능"은 마지막 생성으로만 판정 (§6.2) |
| `--list-models` | 해석된 연결(프로필 포함)의 종류에 맞는 이미지 모델만 보이고 `profile`·`kind`를 함께 냄(연결 해석 실패 때도 같은 키, 모르는 값은 null) | 프로필마다 쓸 수 있는 모델이 다름 (§6.3) |
| 투명 결과 검사 | `background:"transparent"`이면 크기 맞춤 전 공급자 원본에 완전 투명(α=0) 픽셀이 1개 이상 있어야 하고, 맞춤 후 저장 결과에도 남아 있어야 함. 아니면 재시도하지 않는 `provider` 실패로 기록(`status:"failed"`, 이미지 없음). `contain` 여백은 투명 판정에 넣지 않음. Python에는 없음 | 투명이라고 표시했는데 투명 정보가 없는 결과 방지 (§7.3, 검토 F3) |
| 크기 맞춤 | `fit:"cover"`(CLI 기본, Python과 같은 중앙 자르기) 외에 `contain`(투명 여백)과 `original`(공급자 그림을 그 크기 그대로 저장, `saved_size`가 요청 크기와 다를 수 있음). 투명 배경 요청의 기본은 `contain`. 스튜디오 앱은 자르지 않도록 `contain`이 기본 | 투명 소재·모델이 다른 비율로 보낸 그림이 잘리지 않게 (§7.1, P1-02) |
| batch 결과 | `stdout_tail`/`stderr_tail` 없음(자식 프로세스 없음). `concurrency`, `retried` 추가. 실패 20건 뒤 시작하지 않은 계획을 `cancelled` 실패로 보고(Python은 결과에서 빠짐). `count`가 1 미만이면 Python `gen_batch.py`처럼 요청 전에 `invalid_request`. 1000을 넘어도 single처럼 `invalid_request`(Python은 상한 없음) | 프로세스 안 실행, 정직한 결과 |
| 입력 형식 검사 | `reference_images`(최상위·job)는 없음/`null` 또는 문자열 배열만 허용, 그 밖(문자열 하나 등)은 요청 전에 `invalid_request`(job 값은 그 job의 실패). Python은 `list("a.png")`처럼 글자 단위 경로로 바꿈. `image_model`은 모든 연결 종류에서 영문자·숫자·`.`·`_`·`-`만, `..` 없이 최대 128자. Gemini 주소는 모델 ID를 한 경로 요소로 인코딩해 만듦 | 잘못된 입력이 유료 요청이나 다른 서버 경로로 가지 않게 (검토 F5, F7) |
| 시간 값 범위 | `job_timeout_sec`/`timeout_sec`/`CLIPROXY_TIMEOUT`은 Python처럼 0 이하이면 제한 없음, 유한하지 않거나 86400초를 넘으면 `invalid_request`(종료 코드 2). `AI_IMAGE_RETRY_BACKOFF_SEC`은 0–600초 숫자만, 아니면 오류 JSON과 종료 코드 1(Python은 숫자가 아니면 시작 시 실패) | panic 없이 구조화된 오류 (검토 F8) |
| single `count` 상한 | Python처럼 소수는 버리고 1 미만은 1로 보되, 유한하지 않거나 1000을 넘으면 계획·요청 전에 `invalid_request`(종료 코드 2, `dry_run`도 같음). `--schema`의 `count.max_when_single`로 알림. Python은 상한 없음 | 큰 값이 panic·메모리 고갈·대량 유료 요청이 되지 않게 (검토 F8 후속) |
| 홈 경로 | `topic_root`와 참조 경로의 `~`, `~/…`, `~이름/…`을 Python `expanduser`와 같이 펼침(Windows `USERPROFILE` → `HOMEDRIVE`+`HOMEPATH`). preset 경로는 Python처럼 펼치지 않음 | 같은 spec이 같은 폴더를 가리키게 (검토 F9) |
| 실패 순서 | single은 Python처럼 `index` 순, jobs는 `id` 순. batch는 `id` 순(Python `gen_batch.py`는 완료 순서) | 결정적인 결과 (검토 F10) |
| batch 진행 이벤트 | `mode:"batch"`의 `job_*` 이벤트를 stderr에 냄. Python batch는 이벤트 없음 | 앱 진행 표시 |
| preset 상대 경로 | 현재 폴더 → 실행 파일 위쪽 폴더 중 그 경로가 있는 곳. Python은 저장소 루트 기준 | 실행 파일이 저장소 밖에 있을 수 있음 |
| 이미지 픽셀 | 크기와 형식은 같지만 리샘플링 구현(Pillow LANCZOS vs `image` Lanczos3)이 달라 픽셀은 다를 수 있음 | 비결정적 생성 이미지는 바이트 비교 대상이 아님 (§5.3) |
| `elapsed_sec`, `ts` | 비교에서 제외 | 실행 환경 값 |
